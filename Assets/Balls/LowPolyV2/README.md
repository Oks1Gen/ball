# Low Poly V2 — пак мячей (Blender)

Десять low-poly мячей по референсам из `../References/2026-10-31-low-poly-v2/`. Storm сделан по более новому листу с шестью ракурсами `references/08-storm-views.webp`, который заменяет его картинку в общей папке. Вся геометрия процедурная: `build_low_poly_v2.py` пересоздаёт пак с нуля, ручных правок в `.blend` нет.

- Файл сцены: `ball-pack-low-poly-v2.blend` (сцена `BallPack_LowPolyV2`).
- С 2026-10-31 эти мячи стоят в игре. Цепочка такая:
  1. `export_roblox.py` выгружает 10 мешей в один `roblox/balls.glb` и общий атлас цветов `roblox/atlas.png`.
  2. glb загружается через Open Cloud как Model, атлас — как Image.
  3. `make_templates.py` пишет `RojoTest/src/shared/BallTemplates.rbxmx`.

  ID ассетов, выдача прав игре и раскладка по стендам описаны в `RojoTest/assets/balls/README.md`. После пересборки мяча нужно повторить экспорт и загрузку, а в `make_templates.py` обновить MeshId.

## Итоговый пак

`final/` — готовый к передаче набор. В нём по каждому мячу `.glb` и `.fbx` с атласом, сам атлас, файлы для Roblox с ID ассетов, рендеры и копия исходников. `../BallPack-LowPolyV2.zip` — тот же набор одним архивом. Собирается командой `export_pack.py`: она запускается в Blender после `export_roblox.py`, переиспользует его сборку мешей и пишет `final/models` и `final/textures`. Остальное копируется вручную, описание в `final/README.md`.

## Состав

Коллекция `BallPack_LowPolyV2` → по дочерней коллекции на мяч. В каждой: пустышка-корень с тем же именем (радиус мяча ≈ 1 м, корень в центре) и меши частей `<Ball>_<part>`. Материалы — `LP2_<key>`, плоское затенение, оттенок граней берётся из атрибута `lp_shade`. Свет, пол и камеры лежат в `BallPack_Stage`.

- у Leather стежки на всех 30 швах;
- у Steel 8 болтов в вершинах куба, поэтому с каждой оси видна одинаковая четвёрка;
- у Storm раскладка четырёхкратная, нижняя половина зеркалит верхнюю, а фронт, бока и тыл одинаковые, как на референсе.

## Скрипты

Скрипты выполняются внутри Blender 5.2 через аддон Blender Lab MCP (TCP `localhost:9876`; запрос — JSON `{"type":"execute","code":...,"strict_json":false}` с нулевым байтом в конце; код кладёт ответ в `result`). Параметры задаются глобальными переменными перед `exec`.

- `build_low_poly_v2.py` — строит сцену, сцену-стенд и все мячи. `ONLY = ["08", "09"]` пересобирает выбранные мячи; `ONLY = ["none"]` обновляет только стенд.
- `render_previews.py` — фронтальные кадры `previews/review_XX.png` (720 px) и общий план `previews/overview.png`. `WHICH = ["01", "overview"]` ограничивает набор.
- `render_turntable.py` — виды спереди/справа/сзади/слева/сверху, листы `previews/turntable_01-05.png` и `turntable_06-10.png`. Принимает тот же `WHICH`.
- `contact_sheet.py` — сравнение «референс сверху, рендер снизу»: `previews/compare_01-05.png`, `compare_06-10.png`. В `REF_CROPS` задано, какой референс заменён более новым листом и какой его фрагмент брать: для Storm — вид спереди из `references/08-storm-views.webp`.

Порядок после правки: build → render_previews → contact_sheet / render_turntable → сохранить `.blend`.

Рендер: EEVEE, Standard view transform. Мир через Light Path разделён: камера видит лавандовый фон с силой 1.0, освещение идёт от того же фона с силой 0.55. Плюс солнце с силой 3.
