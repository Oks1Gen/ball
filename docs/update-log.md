# Update Log

Источник данных — `RojoTest/src/client/Modules/UpdateLog.luau`. Он хранит версии,
английские тексты, реестр авторов и чистую функцию группировки. `UpdateLogView`
строит содержимое, `HudPanels` сохраняет общие окно, иконку, blur и движение.

## Выпуски и версии

- Начальная точка новой истории — **v0.1.0, 2 ноября 2026**. При миграции удалены
  записи до этой даты; семь сегодняшних записей объединены по итоговому результату,
  добавлен новый журнал. Устаревшие промежуточные варианты не переносятся.
- Дата — `YYYY-MM-DD` по Europe/Moscow. Не вычислять её на клиенте игрока.
  `id` выпуска — `YYYY-MM-DD-vX.Y.Z`, версия — `X.Y.Z` без префикса `v`.
- На одну дату допускается один текущий неопубликованный выпуск. Несколько мелких
  задач дополняют его, сохраняя номер. На новую дату создаётся следующий выпуск;
  предыдущие даты остаются в данных независимо от публикации.
- Patch: `0.1.0 → 0.1.1` для небольших улучшений и исправлений.
  Minor: `0.1.1 → 0.2.0` для новой механики или крупной переработки.
  Major: `0.2.0 → 1.0.0` только для согласованного крупного релиза.
  Количество задач, коммитов и пунктов само по себе номер не меняет.
- Если крупное изменение вошло в текущий неопубликованный выпуск, повысить
  соответствующую часть его версии и обновить `id`, сохранив одну запись.
- `published=false` означает, что выпуск ещё не опубликован в Roblox. Не ставить
  `true` после локальной проверки или синхронизации Rojo. Только фактическая
  публикация игры, отдельно разрешённая пользователем, фиксирует выпуск.
- Опубликованный выпуск не дополнять. Создать следующий номер; при той же дате
  UI покажет его внутри существующей карточки дня. Ошибки в тексте и подтверждённые
  уточнения авторства можно исправлять без выдачи нового игрового обновления.

## Тексты и авторы

- В выпуске обычно 3–5 пунктов, максимум 5; для отдельного срочного исправления
  достаточно одного. Объединять близкие правки; не заполнять список ради количества.
- Категории строго `New` (новое), `Improved` (улучшение), `Fixed` (исправление).
  UI выводит их в этом порядке, без пустых разделов.
- У пункта стабильный `id`, категория, `summary` до 60 символов, необязательный
  `details` до 380 символов (обычно 1–2 предложения) и непустой список `credits`.
  Короткий текст называет результат: `Better kicking controls`. Раскрытые
  подробности объясняют пользу игроку. Не перечислять координаты, CFrame,
  размеры кнопок, внутренние модули и каждый этап одной переработки.
- Каждая запись `credits` содержит ключ `author` из `Authors` и понятный `role`
  (`UI`, `Code`, `Map`, `Gameplay`, `Art` или их сочетание).
  Реестр: `name` — подтверждённый ник конкретного игрока, необязательный `userId` — реальный Roblox
  аккаунт для аватара. Без UserId отображается текст; поддельные аватары не нужны.
- Авторство не выводить из текущего игрока, владельца place или Git автоматически.
  Пользователь явно указал **только Dakemo555** для всей миграции 2026-11-02,
  UserId **11789507527** подтверждён Studio MCP. Для будущего вклада использовать
  подтверждённого игрока и явно описывать в подробностях каждого пункта, что именно
  он сделал. Если игрок или его вклад неизвестен, уточнить у пользователя до
  добавления записи; не придумывать авторство.
- Строго запрещены коллективные и безличные подписи: `Ball Team`, `Team`,
  «команда», «разработчики» и аналоги. Нельзя подставлять команду вместо игрока.
  ИИ, AI, Codex, ботов и инструменты нельзя упоминать как авторов или исполнителей
  нигде в Update Log: ни в реестре авторов и `credits`, ни в заголовках,
  кратких текстах или подробностях. В каждой записи должны быть конкретные
  игроки и их подтверждённый вклад.

## Отображение

- Одна карточка на дату; в ней все выпуски этого дня, новые версии сверху.
  Сортировка числовая: `0.1.10` новее `0.1.9`.
- Окно показывает четыре последние даты. Группировка сортирует копию данных,
  не удаляет историю и не обрезает несколько выпусков четвёртого дня.
- В шапке — дата, версия, заголовок, уникальные авторы с аватарами при наличии.
  Краткие пункты с маркерами раскрываются независимо, под ними — подробности
  и авторы с вкладом. Нажатие по фону внутри окна его не закрывает.
- Кнопки используют общий UiMotion. Раскрытие занимает 0.2 s; при отключении
  анимаций выполняется мгновенно, включая прерывание активного перехода.
  Уничтожение окна отменяет переходы и отключает подписки.

## Порядок обновления

1. Завершить и проверить изменение поведения игрока.
2. Найти текущий выпуск на эту дату. Объединить мелкие изменения и повторы;
   новую версию создавать по правилам выше. Обновить `id` при смене версии.
3. Проверить итоговые тексты, категории, авторов и вклад. Не записывать планы.
4. Запустить `node RojoTest/tools/check.mjs`. В его Lune-набор включён
   `tests/UpdateLog.spec.luau`: группировка дат, сортировка версий, лимит,
   уникальность записей и корректность текстов/авторов.
5. Через Studio MCP на ПК проверить окно, раскрытие, сворачивание, прокрутку,
   аватар/подписи, читаемость и закрытие. Временные данные проверок удалять.
   Мобильные проверки — только по отдельной просьбе или перед релизом.

Эти действия не разрешают коммит и публикацию игры.
