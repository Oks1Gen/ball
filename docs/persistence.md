# Сохранения и покупки

ProfileService использует настоящую ProfileStore. Выбор окружения находится только на сервере в `src/server/ProfileStorage.luau` и определяется `RunService:IsStudio()`, а не запросом клиента.

| Окружение | Постоянное хранилище | Импорт прежних данных |
|---|---|---|
| Studio | `BallProfiles_Studio_v1` | Не выполняется; Production не читается |
| Production | `BallProfiles_v1` | `StoneSkipping_1`, только чтение |

В обоих случаях ключ — `Player_<UserId>`, данные — `profile.Data.progress`; `version = 1` обозначает завершённую инициализацию/перенос. Имя Production сохранено, чтобы не сбросить существующие live-профили. Studio теперь сохраняется между остановками Play и перезапусками Studio. `store.Mock` не используется в игровых сессиях; старые данные из Mock после завершения того Play восстановить нельзя.

Библиотека лежит в `ServerStorage.ServerPackages.ProfileStore`. Сервис и конфигурация окружений — в `ServerScriptService.Server`; они не реплицируются клиентам. `check.mjs` проверяет маршруты этих трёх модулей по Rojo sourcemap и SHA-256 библиотеки по закреплённому upstream-исходнику. В ReplicatedStorage остаются только чистые правила/схема и клиентский снимок прогресса без чеков; таблицы профилей и сохранения там не создаются.

Перед загрузкой сервис ждёт завершения проверки доступа ProfileStore (до 20 секунд). Если API недоступно, игра не выдаёт временный профиль и сообщает причину: библиотека умеет молча переходить к памяти при отключённом API, но для игровых сессий такой fallback запрещён. Для Studio требуется опубликованный place и включённое **Game Settings → Security → Enable Studio Access to API Services**. В текущем place доступ подтверждён реальной записью и повторной загрузкой после остановки Play.

При первом live-входе сервис читает прежний `StoneSkipping_1`, ключ `u_<UserId>`. Старое хранилище остаётся неизменным. Валюта, Skill, rebirths, рекорд, открытые предметы и миры, питомцы с дробными усилениями, экипировка, настройки и обработанные чеки переносятся. Некорректные числа и ссылки очищаются чистым модулем ProfileData.

Ошибка чтения хранилища, некорректная запись и действующая аренда старого сервера прерывают вход без выдачи свежего прогресса. Сессия завершается с `version = 0`, и следующий вход повторяет перенос. Это намеренная защита от потери прежнего прогресса: `version = 1` ставится только после успешного чтения и проверки, включая подтверждённое отсутствие старой записи. В Output остаётся предупреждение `[Ball profiles]` без UserId и ключа хранилища. Некорректную старую запись необходимо восстановить отдельно; ошибка больше не маскируется созданием пустого профиля.

Пока перенос не завершён, игрок защищён от повторного входа: флаг загрузки держится до публикации профиля, поэтому второй параллельный `Load` того же игрока не запускает вторую сессию ProfileStore (она отвергла бы её и выбросила игрока).

Перед публикацией этой миграции необходимо завершить серверы старой версии и дождаться завершения их аренд. Автоматического двустороннего переноса нет: возвращать старую версию игры после накопления новых данных без отдельного плана миграции нельзя.

ProfileStore отвечает за блокировку сессии, периодическое сохранение и финальное сохранение при завершении сервера. Выход игрока вызывает EndSession. Потеря сессии отменяет тренировку/бросок, освобождает streaming focus и завершает вход игрока. UserId привязывается к профилю через AddUserId.

Админ-тест хранит исходный прогресс отдельно. OnSave и OnLastSave подставляют именно исходный прогресс; сброс тестового состояния не попадает в live-профиль. Покупки за Robux во время админ-теста запрещены.

ProcessReceipt начисляет продукт на сервере и записывает PurchaseId без yield между этими действиями. Повторный чек не начисляется повторно. PurchaseGranted возвращается только после появления PurchaseId в `LastSavedData`, то есть после подтверждённого сохранения ProfileStore. При тайм-ауте возвращается NotProcessedYet, чтобы Roblox повторил обработку; отметка в текущем профиле предотвращает повторное начисление. Ожидание подтверждения чека идёт под отдельным флагом и не держит флаг сохранения: выход игрока и автосохранение не ждут его 15 секунд.

Платный Skip Rebirth использует общий серверный rebirth: останавливает тренировку и не применяется во время броска. Пока бросок идёт, чек остаётся необработанным для повторной обработки; PurchaseId записывается только после применения награды.

Продукт AdminEgg одноразовый: оплаченная награда ставит `perks.AdminEgg`. При полном инвентаре вместе с PurchaseId сохраняется обязательство `perks.AdminEggPending`. Оно переживает повторный вход и нормализацию профиля; подтверждение чека означает сохранённую награду или сохранённое обязательство её выдать. Удаление питомца и начало следующей игровой сессии пытаются выдать резерв при наличии свободного слота. Выдача снимает Pending, обновляет инвентарь и запускает сохранение; повторный чек не создаёт второй резерв. Лимит 60 сохраняется. Всплывающее окно показывает захваченного при выдаче питомца.

Skill, Wins, rebirths, best и daily ограничены максимальным точно представимым целым `9007199254740991`. Начисления используют тот же предел, что нормализация при загрузке. Старые корректные Skill/Wins выше прежнего предела 10¹⁵ теперь сохраняются. Порог требуемого Skill для rebirth остаётся 10¹⁵ и не меняет баланс.

Офлайн-награды: `lastSeen`, дробная `offlineRate` и незабранная `offlinePending`
сохраняются в прогрессе. Загрузка добавляет 25% скорости лучшей доступной
тренировочной дорожки за максимум 12 часов. Ставка фиксируется при сохранении:
учитывает rebirths, экипированных питомцев, мяч, DoubleSkill и мир; временный
бонус друзей не действует офлайн. Первый вход/старый профиль без timestamp
не получает выдуманную награду. Незабранная сумма переносится на следующий вход.
`OfflineClaim` не принимает сумму клиента; сервер переносит pending в Skill
и обнуляет его без yield. Повторное нажатие не начисляет повторно. При аварии
последней отметкой онлайна остаётся последнее успешное автосохранение.

Daily использует прежний `daily` (номер UTC-дня) и `dailyCount` (0–7).
За один UTC-день доступно одно получение; пропуск дня не сбрасывает прогресс.
После дня 7 новый круг доступен со следующего дня. Награды по дням:
100 Skill; 500 Wins; 500 Skill; 1.5K Wins; 2K Skill; 5K Wins;
10K Skill + 10K Wins. Правила и баланс — `shared/Core/ReturnRewards.luau`.
Snapshot передаёт серверные `welcome` и `dailyReward`; клиентский календарь
не решает доступность по локальным часам.

Идентификаторы продуктов в GameConfig пока равны нулю. По просьбе пользователя кнопки Shop, HUD и Skip Rebirth активны и показывают прежние цены даже при ID=0; сервер отвечает `This purchase is not available yet`, не запуская реальную оплату. Auto Kick также можно открыть за 2.5K Wins. Нельзя подставлять вымышленные ID или подтверждать реальные оплаты через Mock. Финальная проверка Production и настоящих чеков нужна в опубликованной тестовой среде.
